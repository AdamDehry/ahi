# Onboarding implementation decisions

November 3, 2026. All decisions apply to this branch’s downloadable setup app. Nothing is merged, deployed, pushed, restarted or connected to the owner’s production installation.

| Decision | Choice and reason | Swappable boundary / consequence |
| --- | --- | --- |
| Desktop shell | Electron 45, isolated renderer, sandboxed preload and narrow command bridge. One JavaScript service can drive folder operations, official CLIs and three installer families. | `ui/` talks only to `invoke(method, argument)`. `SetupService` is independent of Electron and has injected filesystem capability, runner, keychain, browser opener and HTTP client. A Tauri/native shell can replace `main.cjs` / `preload.cjs`. |
| Packaging | DMG on native Intel and Apple Silicon macOS runners, NSIS on Windows x64, AppImage on Linux x64. Manual workflow only, read-only repository permissions, artifact upload only. | The workflow builds review installers, never creates a GitHub release, publishes, pushes a tag or changes visibility. macOS/Windows artifacts have not been built on this Linux host. Signing, notarization and distribution are outstanding release work. |
| Runtime bootstrap | Bundle a portable official Node 22.22.2 binary, verified against the official release checksums, with license and provenance. Bundle npm for local CLI installs and unpack the full production dependency tree so portable Node can resolve npm’s hoisted dependencies without Electron’s ASAR loader. | Owner computers need neither Node nor npm installed globally. Provider tools stay inside the chosen AHI home. npm’s dependency advisory findings are recorded; this preview is not cleared for public release. |
| Provider login | Launch each provider’s own CLI in a native terminal: Claude auth login; Codex login; Gemini interactive Google sign-in. No OAuth implementation and no token extraction. | Provider adapters and package names live in `catalog.cjs`. A native terminal keeps browser callbacks/terminal prompts under the official CLI’s control. Subscription access is used only through that CLI; it is not represented as generic API access. |
| Real connection gate | Require official login status where supported and one small model reply. Gemini is checked with its actual noninteractive command because it has no auth-status command. Recheck the default at finish. | Can use any one provider, including Gemini or Codex alone. Each check may consume provider quota/credit. Actual model catalogs and the agent identity remain the runtime’s responsibility. |
| CLI compatibility | Read installed package bin metadata. JavaScript bins run with bundled Node; native bins run directly. npm script policy names the official packages and their native dependencies. | Real install checks caught Claude’s native binary and npm 12’s install-script policy. This avoids hardcoding every CLI as JavaScript. |
| State and home | Durable, serialized atomic JSON saves; stable setup ID; explicit folder choice; empty home only; Personal, Work, AHI_OS. Save interrupted folder claim and resume it. Reject links in managed roots. | No existing installation is adopted, moved or rewritten. No new memory/indexing system. Existing-install migration is separate work. Setup state is local to this app, not a public account service. |
| Voice keys | Native `@napi-rs/keyring`: macOS Keychain, Windows Credential Manager, pinned Linux Secret Service. No silent Linux in-memory fallback. Environment fallback requires explicit consent. | UI and setup state hold references/status only. The fallback directory is mode 0700 on POSIX; Windows uses an explicit user-only ACL before writing. Account/key verification is separate from speech-model availability. |
| ElevenLabs verification | Verify `/v1/user`, not the public voice list. | The live unauthenticated probe showed `/v1/voices` can return 200 without a key. That endpoint would falsely verify a pasted string. The private user endpoint returns 401 without authentication; limited keys need permission for this account check. |
| Remote access | Official cloudflared download with GitHub release asset SHA256; official browser login; named tunnel; explicit DNS route; loopback origin; user starts/stops a tracked child. Refuse route/start unless the separate runtime advertises readiness and denies unauthenticated session access. | No Quick Tunnel, no automatic background system service, no domain purchase, no current gateway integration invented. Runtime readiness endpoints are a new proposed contract, not existing gateway routes. A full phone/PWA test remains pending that integration. |
| VPS mode | Same app with `--ozone-platform=headless --disable-gpu --headless-setup`; bundled Node runs the same real service over loopback HTTP, ephemeral pairing code, HttpOnly/SameSite cookie, origin/Host checks and pairing attempt limit. Use an SSH local forward. Official logins run from generated scrubbed scripts in the SSH terminal. | No display needed and no pairing or provider secret in URLs. This is a private setup grant, not an AHI owner token. The CLI home remains on the VPS. Provider-specific headless login/browser callback requirements still apply. Port 4189 is used: this runtime rejects 4190 as a bad port. The native server process is stopped with its parent. |
| Completion | Write one `AHI_OS/setup-handoff.json` with default provider, local CLI homes, safe credential references, optional tunnel state and requested connections. | This branch does not ship the full chat gateway or silently launch it. Handoff marks the agent runtime pending. No fake owner token, agent conversation or “connected” plugin is invented. |
| Browser preview | Same UI, loopback server, real filesystem service inside an explicit workdir sandbox, labeled fixture sign-ins and disabled voice-key submission. | The preview is safe to inspect and cannot connect a live account. Native UI smoke and real CLI binary checks are separate evidence. Fixture success is never reported as live provider authorization. |

Primary references actually checked: [Codex authentication](https://developers.openai.com/codex/auth), [Claude CLI reference](https://code.claude.com/docs/en/cli-reference), [Gemini authentication](https://geminicli.com/docs/get-started/authentication/), [native keyring binding](https://github.com/Brooooooklyn/keyring-node), [Cloudflare named tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/create-local-tunnel/), [ElevenLabs user endpoint](https://elevenlabs.io/docs/api-reference/user/get), and [GitHub runner architectures](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job).
